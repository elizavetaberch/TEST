# Barrierefreiheit (доступность)

Внутренний материал: Vortrag David'а в Confluence («Barrierefreiheit Vortrag von David») — Button, Breadcrumb, Navigation, Accordion, Tabs, Slider, Formular, Modals, Feed.

## Главный принцип

> No ARIA is better than bad ARIA.

Нативные элементы дают доступность бесплатно. Самодельные на `div` требуют `role`, `tabindex`, `aria-expanded`, `aria-controls`, ручной обработки Enter/Space — и обычно это делают наполовину.

## `<details>` / `<summary>`

Что даёт браузер сам:
- `<summary>` фокусируемый, работает Tab
- Enter и Space раскрывают
- скринридер объявляет как кнопку и говорит collapsed/expanded
- работает без JS

> [!danger] Не добавлять `aria-expanded` руками
> Браузер уже сообщает состояние. Ручной атрибут не обновляется и начинает врать скринридеру.

В подходе David'а используется `<a>` вместо `<button>`, потому что внутрь кнопки нельзя положить заголовок. **У `<details>` этой проблемы нет** — `<h3>` внутри `<summary>` разрешён, и вопросы попадают в структуру заголовков (навигация клавишей H).

`role="region"` на панелях — WAI-ARIA APG **не советует** при нескольких панелях: список ориентиров превращается в кашу.

## Декоративные иконки

```html
<span aria-hidden="true" class="shrink-0">
  <ausProject:svgInline path="..." class="..."/>
</span>
```

До: в aria-дереве был лишний `- img`. После — чисто:
```yaml
- group:
  - heading "Question1" [level=3]
```

## Как проверять

**1. Клавиатура (главное, всегда)**
- Tab проходит по всем интерактивным элементам
- **фокус видно** — рамка/обводка (WCAG 2.4.7)
- Enter / Space работают
- порядок совпадает с визуальным

**2. DevTools → панель Accessibility**
- **Name** = текст элемента (а не «chevron right»!)
- **Role** = button / disclosure triangle

**3. Lighthouse** → только Accessibility → Analyze (30 секунд, ловит контраст и alt)

**4. NVDA** (бесплатный скринридер для Windows) — выключение `Insert + Q`

**5. Автоматически** — см. [[Тесты Playwright]]: `.aria.yml` + axe-core
